# Nagi 需求文档

&gt; 当前状态：v0.1 已完成；v0.2 功能实现与专项验收完成，正在进行文档、全量回归和版本收尾。

## 项目目标

- 做一个能语音对话的交互式数字人：用户对着麦克风说话，系统完成语音识别、LLM 回复和语音合成，Unity 中的 3D 角色带着表情和动作开口回答。
- 通过逐版本迭代，完整走一遍客户端、后端、数据库、Web 后台、图形、工程化和 AI 的开发流程。
- 保持系统开源、可定制，使用户能够修改人设、音色和客户端表现。
- 最终产出包括可运行的 Windows 程序、各版本开发日志、技术博客和演示视频。

## v0.1 既有能力与兼容要求

以下能力已经实现，后续版本不得无故破坏：

- Unity 按键录音并通过 WebSocket 发送 WAV 音频。
- Whisper 在本地完成语音识别。
- DeepSeek 根据人设和用户输入生成角色回复。
- Edge TTS 合成回复语音。
- Unity 播放回复并在 Idle／Talking 动画之间切换。
- Pipeline 分层处理 ASR、LLM、TTS 等阶段异常。
- WebSocket 使用 `request_id` 配对请求和响应。
- 网络操作有限重试，单次请求异常不应导致整个服务退出。

v0.2 允许在响应中新增字段，但旧 Unity 客户端应能忽略 `session_id` 并继续工作，不要求大规模重写客户端。

## v0.2 功能需求与完成情况

### 1. MySQL 数据层

**需求：**

- 保存用户、人设和完整对话记录。
- 每轮对话用一条记录保存用户输入和角色回复。
- 对话记录关联用户、人设、Session ID 和 Request ID。
- 支持按会话查询最近 N 轮，并按时间正序构造 LLM 历史。
- 支持日志分页、Session ID 筛选、情绪筛选和情绪分组统计。
- 初始化脚本可以重复执行，不重复创建默认用户，不用文件覆盖已有数据库人设。

**状态：已完成。**

### 2. 数据库人设

**需求：**

- Pipeline 每轮读取当前启用人设。
- MySQL 是运行期间的人设权威来源。
- `backend/config/persona.md` 仅用于首次初始化导入。
- 网页可以读取、编辑和保存启用人设。
- 名称和内容需要非空校验，保存失败后保留用户输入。
- 修改保存后影响后续对话，不要求修改 Python 代码。

**状态：已完成。**

### 3. Redis 最近上下文缓存

**需求：**

- 使用 Redis List 保存同一会话最近 N 轮。
- 每轮以 JSON 保存一对 `user_text` 和 `assistant_text`。
- 追加后裁剪到最近 N 轮，并设置或续期 TTL。
- 缓存命中时直接构造历史。
- 缓存未命中或损坏时，从 MySQL 查询并重建。
- Redis 不可用时回退 MySQL，不阻断语音主流程。
- Redis 恢复后避免使用故障前的旧上下文。

**状态：已完成。**

已修复 Pipeline 中 Redis 追加代码缩进错误导致的“第二轮正常、第三轮开始一直只有一轮历史”问题，并增加四轮自动化回归测试。

### 4. 多轮对话

**需求：**

- 每次 WebSocket 建连生成独立 `session_id`。
- 同一连接共享会话上下文。
- 默认把最近 10 轮发送给 LLM。
- 历史只能包含 `user` 和 `assistant` 消息，不允许历史注入 `system`。
- 当前用户输入位于消息列表末尾。
- 超过 10 轮后逐步淘汰最旧轮次，MySQL 完整记录不删除。
- `context_turns=0` 时可以禁用历史。

**状态：已完成。**

**已验证行为：**

```text
历史轮数：0、1、2……9、10、10、10……
```

达到 10 轮后，最早信息不再进入 LLM，但后续信息仍能正确使用。

### 5. FastAPI 管理接口

**需求：**

- 提供健康检查。
- 提供启用人设读取和保存。
- 提供对话分页、Session ID 和情绪筛选。
- 提供情绪统计。
- 提供白名单音色试听。
- 对分页参数、人设内容和试听文本进行校验。
- JSON 响应显式使用 UTF-8，避免 Windows PowerShell 中文乱码。
- CORS 仅允许本地管理后台开发地址。
- 数据库异常可映射为实时协议中的 `DB_FAILED`。

**状态：已完成。**

### 6. Vue 管理后台

**需求：**

- 提供人设配置、对话日志和音色试听三个页面。
- 显示 API、MySQL 和 Redis 健康状态。
- 人设页面支持脏状态检测、保存反馈、错误保留输入和未保存离开保护。
- 日志页面支持分页、筛选、空状态、错误重试和完整文本展开。
- 情绪统计显示数量、百分比和总数，统计不受分页影响。
- 试听页面支持音色选择、文本校验、生成状态和浏览器音频播放。
- 及时释放不再使用的音频 Object URL。
- 支持窄屏布局、可见焦点和减少动态效果偏好。

**状态：已完成。**

## 核心验收标准

### 数据与会话

- 同一 WebSocket 连接中的记录使用同一个 `session_id`。
- MySQL 能保存每轮用户输入和角色回复。
- TTS 失败时，已经生成的文字对话仍保留。
- Redis 追加失败不会删除 MySQL 数据。
- 重连后创建新会话，不错误混入旧会话上下文。

### 最近 10 轮

- 前 10 轮历史数量逐轮增加。
- 第 11 轮开始保持 10 轮。
- 第 11 轮仍能使用第 1～10 轮信息。
- 下一轮淘汰第 1 轮后，模型上下文中不再包含该轮。
- 被淘汰的历史仍可通过 MySQL 和网页日志查询。

### 缓存回退

- Redis 未命中时可以从 MySQL 重建。
- Redis 不可用时主流程可以继续。
- 缓存恢复后能够重新校准，不持续读取旧历史。
- 缓存异常不会被误报为“模型没有记忆”。

### 管理后台

- 人设保存后能从 API 和数据库重新读取到相同中文内容。
- 日志分页、组合筛选和空结果行为正确。
- 非法分页参数返回校验错误。
- 音色试听返回 `audio/mpeg`，且不产生对话记录。
- 情绪统计与数据库记录一致。
- 前端生产构建成功。

### 自动化回归

至少覆盖：

- Repository 写入、最近历史和分页筛选；
- LLM 消息结构；
- Redis 重建、命中、追加、裁剪和故障降级；
- Pipeline 连续四轮历史为 0、1、2、3；
- Pipeline 四轮 MySQL 记录和 Redis 缓存一致；
- WebSocket 同连接共享 Session、新连接创建新 Session；
- 人设、日志、统计和 TTS API。

## 当前记忆边界

v0.2 实现的是：

&gt; 同一 WebSocket 连接的最近 10 轮短期上下文，加上 MySQL 中的完整对话记录。

它不等同于：

- 跨连接自动恢复旧会话；
- 从全部历史中检索相关事实；
- 永久记住用户所有偏好；
- 向量数据库支持的长期语义记忆。

此外，历史已经成功传给 LLM，不代表模型每次都会稳定引用。模型回答质量与数据层是否正确传递需要分别验收。

## 非功能要求

### 可维护性

- ASR、LLM、TTS、数据库和缓存职责尽量分层。
- 数据访问集中在 Repository，避免在接口和 Pipeline 中重复拼写查询。
- 关键数据流应有自动化测试，不能只依赖模型偶尔回答正确。
- 新功能优先小步修改，避免不必要的大规模重写。

### 可靠性

- 外部网络操作有限重试。
- Redis 故障安全降级。
- 每轮使用独立回复音频文件，避免并发覆盖。
- 测试产生的数据库记录、缓存和临时音频应自动清理。

### 安全与配置

- `backend/.env` 和 `web-admin/.env.local` 不提交到 Git。
- 不在日志、文档或截图中公开真实 DeepSeek API Key。
- 示例数据库密码仅用于本地开发。
- 当前管理接口无鉴权，不应直接暴露到公网。
- Mixamo FBX 不入库，仅保留必要 `.meta`，资源下载和使用遵守授权。

## 当前已知限制

- 仅面向 Windows 本地单用户体验。
- 没有登录、JWT 和权限控制。
- 重连后开启新会话，暂不自动恢复旧会话。
- 默认只有最近 10 轮进入 LLM。
- 情绪标签固定为 `neutral`，情绪统计不代表已完成真实情绪识别。
- 数据表使用 SQLAlchemy `create_all` 初始化，尚无正式迁移工具。
- Edge TTS 依赖外部网络。
- Whisper base CPU 可能误识别部分语音和英文专名。
- 当前演示视频不阻塞 v0.2 功能和版本验收。

## 后续优先需求

### v0.3 会话恢复

- 客户端能够保存并回传稳定的会话标识，或使用独立的 `conversation_id`。
- 重连时可选择继续最近一次会话。
- 服务端从 MySQL 恢复最近 N 轮并重建 Redis。
- 未携带会话标识时仍创建新会话，保持旧客户端兼容。
- 不将全部历史无限制发送给 LLM。

### 更后续的长期记忆

- 从完整历史检索与当前问题相关的内容。
- 区分短期上下文、用户偏好和长期事实。
- 控制记忆冲突、过期信息和 Token 成本。
- 长期记忆不得绕过用户隔离和权限边界。

## 明确不做什么

- 不训练大语言模型或大型语音模型，只调用现成 API 或开源模型；仅考虑训练小型情绪分类模型。
- 不做手机端或网页端数字人；Vue 仅作为管理后台，实时数字人仍使用 Windows Unity 客户端。
- 不以大规模并发为目标，优先保证单用户体验流畅。
- 不做支付、商业化账号体系或复杂多语言管理界面。
- v0.2 不为了 Redis 引入 Docker，不提前拆分微服务。
- 美术自建模型支线不阻塞主线版本进度。
